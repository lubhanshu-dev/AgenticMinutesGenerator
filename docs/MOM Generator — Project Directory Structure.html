Agentic MOM Generator

Companion to the HLD and the Tech Stack & Team Split note. This note is working/planning material, not part of the formal design doc.

The layout below maps 1:1 onto the HLD's component table — each package holds exactly the classes assigned to it, and the top-level split (audio/, transcription/, diarization/ vs. agents/, llm/, persistence/, monitoring/, evaluation/, api/) mirrors the Person A / Person B ownership split.

2. Why This Structure

  • core/ is the contract layer. It holds nothing but interfaces, event schemas, and shared models — no business logic. Both people import from it, neither person owns a class inside another's package. This is where the Week-1 shared contracts from the planning note physically live.
  • One package per HLD component group, not one file per class dumped into a flat folder — audio/, transcription/, diarization/ mirror Person A's ownership table exactly; agents/, llm/, persistence/, monitoring/, evaluation/, api/ mirror Person B's.
  • tests/unit/ mirrors src/ 1:1 — a test file's location tells you unambiguously which package (and which person) it belongs to.
  • transcript_aggregator.py sits at the bottom of Person A's tree deliberately — it's the file whose output schema (core/models.py) is the actual handoff contract.
  • data/ is gitignored — audio and transcripts are local, potentially sensitive, and should never end up in version control, consistent with the local-first NFR.
  • frontend/ is separate and optional — if you go with a minimal HTML/JS UI instead of React, this folder can be dropped entirely without touching src/.

3. Ground Rules for the Split

  1. Nobody edits inside the other person's package directly — if agents/ needs something from transcription/, it goes through the shared core/models.py object, not a direct import of an internal class.
  2. Any change to core/ (events, interfaces, models) needs a quick sync between both people before merging — it's the one place where a silent change breaks the other person's work.
  3. Mirror new modules into tests/unit/ as you go — don't let test structure drift from src/ structure.
